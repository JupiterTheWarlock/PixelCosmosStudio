# v2 验证记录

## PixelSpace fork 去像素化

2026-09-30，Godot 4.4.1 Compatibility / AMD RX 6700 XT：`test_sky_smooth.gd` 通过。测试画面中，星云从 7 种离散颜色变为 445 种、星尘从 9 种变为 568 种；平滑输出不受像素密度和点阵设置影响，噪声仍可变化并完整循环。远景行星检出 979 个半透明边缘像素，straight alpha 与背景合成误差低于 0.005。

同时验证保存并回读的 Godot Sky 正确合成透明颜色、实时预览不因透明导出选项改变观感。UI 开关和预览过滤、天空接缝、实际天空方向、动态动画、标准导出及 GLB 回读检查均通过；GLB 回读仍为 0 像素变化。常规导出/回读测试退出时仍有下文记录的 GLES3 纹理释放错误，本次专门的去像素化测试退出无此错误。

实现范围与操作见 [fork 复用说明](SKY_FORK_REUSE.md)，结果在 `exports/smooth/report.json`。

## 动态噪声

Godot 4.4.1 Compatibility 实测：云、海水、气态、星云在四分之一周期时均有变化；第 0 秒与完整周期末逐字节一致；幅度为 0 时恢复静止。海水变化时陆地颜色固定，星云变化时星点固定。变化中的六面共同方向仍一致。实际运行空间材质、天空材质、分段光照与体素预览均完成渲染。

8 帧小尺寸 PNG 动画实际导出完成，配置与算法版本/哈希对应；中途取消保留未完成标记。报告与截图在 exports/motion。动画测试涉及两次导出，退出时有 4 条既有 GLES3 纹理释放错误；不将测试断言通过表述为引擎退出日志完全无错误。

像素阈值会令部分像素逐格变化；默认导出为 4 帧/秒，而实时预览连续计算，需提高导出帧数才能获得更顺滑的帧序列。噪声算法按球面方向计算；体素帧播放需要方向采样材质，不能直接用没有 UV 的顶点色模型替换普通贴图。

后续验证范围：按用户要求，不再单独启动 Unity、three.js 或 UE 做导入跑通测试。下方跨引擎记录仅是历史结果。界面调整只在本工具内检查。

界面对齐：左侧预览、右侧常用/高级/配置；使用原版色板列表、紧凑色块、滑条与直接图层开关。test_ui.gd 验证参数范围、滑条自动更新、图层自动更新、生成期间最后一次修改生效、重置配色不影响种子，以及点击原版配色后结果可导出。报告为 exports/v2/ui_report.json。

## 天空顶部方块修复

发现旧版仅验证了生成图片的共同边缘，遗漏了天空盒上传后的实际方向。Godot 4.4.1 的 GLES3 源码按 -X,+X,-Y,+Y,-Z,+Z 上传 Cubemap，与文档的顺序相反，导致正反面错位和顶部方块断层。

修复后 sky.res 与预览显式按方向读取六张纹理，不依赖上述后端顺序。额外的 sky_cubemap.res 对当前 4.4.0/4.4.1 Compatibility 后端补偿；该二进制资源不建议直接切换渲染后端，跨后端优先用 sky.res 或标准六面 PNG。

新增 test_sky_mapping.gd：以方向编码图验证真实 Cubemap 采样、保存后的 Sky 资源，以及朝上、朝下、斜向跨面等 6 个相机视角。结果写入 exports/v2/sky_mapping_report.json。新增实际星空顶部、底部和跨面截图 sky_view_*.png。

源码依据：[Godot 4.4.1 GLES3 texture_storage.cpp](https://github.com/godotengine/godot/blob/4.4.1-stable/drivers/gles3/storage/texture_storage.cpp)，_cube_side_enum。

2026-09-21，Windows / AMD RX 6700 XT。
